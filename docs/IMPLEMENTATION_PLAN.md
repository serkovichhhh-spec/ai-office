## Фаза 2 — Розширення маркетингу, ~5–8 днів
- Перенесення ролей зі скілів Claude Projects (з провенансом і тестами промптів) — потрібен експорт.
- Research/performance-агент на справжніх даних: Meta Ads, Supermetrics / GA4 (read-only інструменти).
- Реєстр знань: approved / draft, свіжість, конфлікти; імпорт рішень та інсайтів із `cmo.space_documents`.
- Розклади (тижневий підсумок, скан конкурентів) — **узгодити з наявними агентами chief/analyst, щоб не дублювати**.
- Telegram / in-app сповіщення для затверджень з телефону.
- Запис затверджених результатів у CMO як пропозицій через `cmo.agent_upsert` (лише дозволені розділи).

## Фаза 3 — Піксельний офіс, ~5–7 днів
- PixiJS: сцена на подіях `office.events` (той самий контракт, що й стан команди у фазі 1).
- Режим низької продуктивності, `prefers-reduced-motion`, мобільний fallback на панелі.

## Фаза 4 — Локальний продакшн, ~4–6 днів
- Аудит `Videos\ProdProd-Studio` **лише читанням** (потрібен дозвіл).
- Міст Windows: вихідне опитування `handoffs`, токен пристрою, офлайн-черга, колбеки статусу.
- Адаптер до `/produce` **без змін** його логіки й BAT-лаунчера; регресійна перевірка.

## Фаза 5 — Hardening
Алерти (зависання lease, бюджет), навантажувальні тести, онбординг інших workspace (GTU, TYAMA, ProdProd), аудит безпеки, тест відновлення з бекапу.

## Альтернативи, що розглядались
| Варіант | Чому ні (зараз) |
|---|---|
| Розширити CMO Space | Статичний, без сервера; ризик зламати робочий інструмент команди |
| Окремий воркер (Railway/Fly) | Ще один сервіс і рахунок; для коротких кроків вистачає Cron + lease |
| Vercel Workflow / Inngest | Сильні варіанти, якщо кроки стануть довгими; контракт кроків сумісний з переходом |
| Відкрити `office` у PostgREST | Більша поверхня атаки; пряме з'єднання з RLS-роллю безпечніше |
